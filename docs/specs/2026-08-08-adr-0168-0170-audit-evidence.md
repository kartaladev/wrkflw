variables in the returned state, while an abort before any match leaves `Variables` untouched.
That is the right answer (the merge is caused by the tier that legitimately fired) but it must
be written down — it is the difference between "the delivery's payload is visible in the
terminal event" and "it is not".

**Fix.** Add to ADR-0169 Decision 4: *"`mergeVars` keeps its merge-once semantics and is not
moved. It runs inside the first tier that matches, so an abort after a match returns state
whose `Variables` carry the delivery payload, and an abort before any match returns them
untouched — the payload is merged by the tier that fired, never by the abort."* Remove the
§9 bullet once stated.

## FINDING D-9 (HIGH) — attack 4: the two guards compose, but the composition exposes that ADR-0168's completion gate can be silently CLOBBERED mid-flight

**Mechanical composition is fine.** Both patches applied together:
```
$ go test ./engine/ ; EXIT=1  (only TestActionCompletedOnTerminalInstanceIsNoOp)
$ go test ./processtest/... ./service/... ./runtime/... ./transport/http/... ; EXIT=0
```

**But the interaction reveals a real hole.** I built the scenario the brief asked for — one
branch starting a compensation walk, another turning the instance non-executable — in the
same delivery:

```
start → saga(doA/undoA, compensable) → fork ⇒
   A: taskA(user) [bndA interrupting "s1"] → rb(CompensateThrow) → endA
   B: catchB(catch "s1") → errEnd(EndError "boom", uncaught)
```
One `SignalReceived{"s1"}` — **measured, both patches applied**:
```
WARN dropping command whose awaiter this step cancelled instance_id=i4 command_kind=InvokeAction correlation_id=i4-c2
AFTER SIGNAL s1: status=compensating tokens=0 boundaries=0 timers=0 activeCmd="i4-c3"
   cmd engine.UpdateTask {…TaskID:i4-h1 … State:cancelled…}
   cmd engine.InvokeAction {CommandID:i4-c3 Name:undoA …}
   RootCompensations=1 Incidents=0
```

Tier 2 starts the local throw walk with cursor **`i4-c2`**; tier 4 then drives branch B into an
uncaught error, `handleUnhandledError` finds `RootCompensations` non-empty and calls
`beginCompensation` **on top of the live walk**, which overwrites `s.Compensating` with a new
cursor **`i4-c3`**. `dropStaleTokenCommands` happens to swallow the orphaned `i4-c2` because
both happen inside one `Step`.

**ADR-0169's `IsTerminal()` guard does not stop any of this** — the instance is
`StatusCompensating`, which is deliberately non-terminal. This is exactly the shape the brief
asked about: *deferring/holding an instance non-terminal lets execution keep driving.*

**And across two `Step` calls the stale filter cannot mask it.** Same definition, `bndA` on
`"s1"` and `bndB` on `"s2"`:
```
AFTER SIGNAL s1 (throw walk starts): status=compensating tokens=1 activeCmd="i5-c2"
   cmd engine.InvokeAction {CommandID:i5-c2 Name:undoA …}          ← dispatched to the runtime
AFTER SIGNAL s2 (uncaught error):    status=compensating tokens=0 activeCmd="i5-c3"
   cmd engine.InvokeAction {CommandID:i5-c3 Name:undoA …}          ← dispatched AGAIN
   RootCompensations=1
```
**`undoA` is invoked twice for one `saga` record**, silently, with no error and no WARN.

**Provenance — this is PRE-EXISTING, not caused by the bundle.** Same two probes on unpatched
`main` (`git checkout -- engine/step_nodes.go engine/step_triggers.go`):
```
MAIN EXIT=0
AFTER SIGNAL s1: status=compensating … activeCmd="i4-c3"   (identical)
AFTER SIGNAL s1 (throw walk starts): … activeCmd="i5-c2"
AFTER SIGNAL s2 (uncaught error):    … activeCmd="i5-c3"   (identical)
```

Root cause, source-verified: `stepCompensateRequested` **does** guard against re-entering a
live walk (`engine/step_compensation.go:150`, `if s.Status == StatusCompensating &&
s.Compensating.ActiveCmdID != ""`), but `handleUnhandledError`'s compensate branch
(`engine/step_errors.go:236-243`) calls `beginCompensation` **directly**, with no such guard,
and `beginCompensation`'s own docstring lists no in-flight check.

**Why it matters to THIS bundle, not just as backlog.** ADR-0168 promotes
`Compensating.ActiveCmdID` from a bookkeeping field into the **instance-completion gate**. A
field that can be silently replaced by an unrelated code path is a fragile thing to gate
completion on, and the ADR asserts nothing about its lifetime. The bundle must at minimum
*state the invariant it is relying on*, and record that it does not hold today.

**Fix (choose one, do not silently skip):**
1. Preferred: add to ADR-0168 a Consequences bullet naming this — *"the cursor is now the
   completion gate, and `handleUnhandledError`'s compensate branch overwrites a live cursor
   without a guard (measured: `undoA` dispatched twice across two Steps). ADR-0168 does not
   fix that; it is filed as its own ADR"* — and add it to the backlog explicitly.
2. Or fold the guard in: `handleUnhandledError`'s compensate branch should take
   `stepCompensateRequested`'s in-flight branch (the walk already in flight *is* the rollback;
   only the terminal outcome needs recording). That is a behaviour change and needs its own
   decision, so option 1 is the honest one for this bundle.

## FINDING D-10 (MEDIUM) — spec §5.1 / ADR-0168 Decision 1 over-generalise: "the fail paths … clear the cursor" is false for the branch that matters

**Spec §5.1 / ADR-0168 Decision 1:** *"`forceTerminate`, cancel and **the fail paths** still
terminate immediately and clear the cursor (ADR-0164)."*

Source-verified. There are **two** fail paths (`engine/step_errors.go:207-251`):

- **failFast** (no compensation records) → `s.endInstance(StatusFailed, …)`, and `endInstance`
  (`engine/state.go:352-356`) does `s.Compensating = compensationCursor{}`. ✅ claim holds.
- **compensate-then-fail** (`len(s.RootCompensations) > 0 || len(s.ArchivedCompensations) > 0`)
  → sets `StatusCompensating` and calls `beginCompensation`. It does **not** terminate
  immediately and does **not** clear the cursor — it installs a *new* one (measured in D-9:
  `i5-c2` → `i5-c3`). ❌ claim false.

And this is not an edge case: it is precisely the path taken whenever the process has anything
to compensate — i.e. every process ADR-0168 is written for.

**Fix.** Replace with a closed enumeration rather than the plural noun: *"`forceTerminate`,
cancel, and the **failFast** fail path (no compensation records) still terminate immediately;
`endInstance` clears the cursor. The **compensate-then-fail** path does not terminate — it
starts its own walk, replacing any cursor already in flight (see [D-9 backlog item])."*
This is the CLAUDE.md quantifier rule: *prefer naming a closed set over counting it*.

## FINDING D-11 (MEDIUM) — the two ESP-site guards are not inert on fallthrough: they retire ESP arms without completing

ADR-0168 Decision 3 presents sites 2 and 3 as *"applied for symmetry and … documented-defensive"*
— i.e. harmless if unreachable. Reading what the fallthrough actually does contradicts
"harmless" if they ever ARE reachable:

- **`exitRootEventSubprocessScope`** (`engine/step_nodes.go:326`): with the conjunct added, a
  live cursor falls past the completion branch into the tail at `:340-342`:
  ```go
  cmds = appendCancelTimers(cmds, c.s.removeEventTriggeredSubprocessArmsForScope(""))
  return cmds, true, nil
  ```
  That **retires every ROOT event-sub-process arm** and returns without completing. The
  instance then sits at `Compensating`, zero tokens, with its root ESPs gone. `rearmRootESP`
  is set only on the **full-reverse** resume plan (`engine/step_compensation.go`, `finishPlan.
  rearmRootESP` docstring: *"Only the full-reverse resume AT ROOT SCOPE sets this"*), so a
  **throw** walk's resume will **not** re-arm them. Net effect if reachable: silent permanent
  loss of root event-sub-processes.

- **`exitNestedEventSubprocessScope`** (`:424`): the same shape — falls to
  `removeEventTriggeredSubprocessArmsForScope(parentScopeID)`.

- Additionally, the tail at `:330-342` carries the comment *"DEFENSIVE, and **unreachable
  today**: the two guards above already established that the root scope holds no token … so
  **nothing can be left for `len(c.s.Tokens) != 0` to find**"*. Adding the conjunct changes
  the entry condition of that very tail, so the comment's stated reason becomes wrong even if
  the tail stays unreached. ADR-0168 **cites this comment as its precedent** for keeping
  defensive guards while simultaneously invalidating it — and neither the ADR nor the plan
  mentions that.

**Fix.** (a) In ADR-0168 Decision 3, replace "applied for symmetry / documented-defensive" with
the measured statement of what the fallthrough *does*: it retires the scope's ESP arms and
returns non-completing. (b) Plan Task 1 must update the `:330` comment: its reason changes
from "nothing can be left to find" to "no token AND no live compensation cursor". (c) If the
reachability construction in Task 1 succeeds, the ESP-arm retirement must be an explicit test
assertion, not an incidental.

			"(this is len(snapshotIDs) == 2 observed from the outside)")
	require.Empty(t, r1.State.Boundaries,
		"fixture control: no boundary arm exists yet — bndT is armed only if catch2 is (wrongly) resumed")

	r2, err := engine.Step(t.Context(), def, r1.State,
		engine.NewSignalReceived(auditT0.Add(time.Second), "y", nil), engine.StepOptions{})
	require.NoError(t, err)

		t.Logf("  token id=%s node=%s state=%v awaitSignal=%q", tok.ID, tok.NodeID, tok.State, tok.AwaitSignal)
	}
	for _, c := range r2.Commands {
		t.Logf("  cmd %#v", c)
	}

	// The terminal event is kept (ADR-0169 Decision 4).
	var fails int
	for _, c := range r2.Commands {
		if _, ok := c.(engine.FailInstance); ok {
			fails++
		}
	}
	require.Equal(t, 1, fails, "T6 control: the FailInstance that killed the instance must be kept")

	// The second snapshotted token must NOT have been resumed.
	for _, c := range r2.Commands {
		_, isTimer := c.(engine.ScheduleTimer)
		require.False(t, isTimer, "T6: no ScheduleTimer may be armed by the second token: %#v", c)
		if ah, ok := c.(engine.AwaitHuman); ok {
			t.Fatalf("T6: no AwaitHuman may be minted by the second token: %#v", ah)
		}
	}
	require.Empty(t, r2.State.Boundaries,
		"T6: no boundary arm may be recorded — bndT is armed only by driving catch2 into taskB")
	for _, tok := range r2.State.Tokens {
		require.NotEqual(t, "taskB", tok.NodeID, "T6: the second token must not be driven into taskB")
	}
	for _, v := range r2.State.History {
		require.NotEqual(t, "taskB", v.NodeID, "T6: taskB must never be visited on a dead instance")
	}
	// The second token is left exactly where it was, still awaiting the signal.
	var stillAwaiting int
	for _, tok := range r2.State.Tokens {
		if tok.NodeID == "catch2" && tok.AwaitSignal == "y" {
			stillAwaiting++
		}
	}
	require.Equal(t, 1, stillAwaiting, "T6: catch2's token stays parked, untouched by the aborted delivery")
}
